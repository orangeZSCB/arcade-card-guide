实验记录

本章记录本次研究的全部实卡实验，按时间顺序。读卡器：PN532 UART。

实验 1：真卡 Konami e-amusement（AIC）dump

对象：Konami 发行的 AIC 卡（DFC 0068）

IDm: 01 2e 61 19 78 53 a3 5d
PMm: 00 f1 00 00 00 01 43 00
块 00 (SPAD0): f5 e1 c0 bd ea 78 f7 a5 52 9d 1a fb 3a 1c 48 7d
块 01-04:      读拒绝（01 B1）
块 82:         IDm + DFC 00 68

SPAD0 用 spad0 算法解密 → 52042115209693652588（520 号段）。 CardCipher 编码 IDm → K7GSNPJBC6CMSR22，与卡背印刷卡号一致。

尝试写 SPAD0：拒绝（01 A6）。

实验 2：空白 UID 卡 → Aime 卡

对象：Gen1a UID 卡，UID BD 65 53 03，SAK 08

意外发现：这张"空白卡"全扇区已被预置 KeyA = KeyB = WCCFv2，访问位 08 77 8F 11 （数据块仅 KeyB 可写）。默认 FF 密钥全灭，mfoc 字典也测不出。 用 MifareClassicTool（Android）dump 才看清。

写入流程（aime_write 工具）：

  1. KeyB WCCFv2 认证成功
  2. 写回测试：块 2 原样写回并回读比对 → 可写 ✅
  3. 写入：
    • 块 1 = 53 42 53 44 + 零（"SBSD"）
    • 块 2 = 00×6 + BCD 50100000003177534211 （= "5010000000" + decimal(UID)，UID 十进制 3177534211）
    • 尾块 = KeyA FF×6 + FF 07 80 69 + KeyB WCCFv2
  4. 重选卡 + KeyB 重新认证，三块回读全部一致
  5. 再次写回测试 → 写后仍可擦写 ✅

块 0（UID）全程未动。

实验 3：真卡 Sega Aime（AIC）dump

对象：Sega 发行的 AIC 卡（蓝白卡面，DFC 0078）

IDm: 01 2e 59 39 99 58 94 b0
块 00 (SPAD0): 37 91 60 26 63 a0 2e c8 cd a4 a2 c0 bf c0 09 69
块 01-04:      读拒绝（01 B1）
块 05-0D:      全零
块 0E:         全 FF
块 82:         IDm + DFC 00 78

SPAD0 解密 → 50142788364534652126（501 号段）。 这张 Sega 卡注册过 Konami——AIC 互认的活证据。 CardCipher(IDm) → KJAL9Z3HLEGALM2P。

实验 4：AIC 卡安全写测试

对实验 3 的卡（注意：写入全部走服务码 0x000B）：

  1. 全量备份可读块（23 块）到文件
  2. 选空白块 0x0D 做"写图案→回读→还原→回读"可逆测试
  3. 结果：全部写拒绝（01 A6）——0x0D、0x05、0x0E 均如此
  4. SPAD1（0x01）写探测：同样 01 A6 拒绝
  5. 全卡比对备份：零差异，卡无损

当时的结论：正版 AIC 卡用户区整体写锁。

这个结论后来被实验 6 推翻

01 A6 是服务码 0x000B 的只读属性造成的，不是发行商写锁。 读写服务是 0x0009。实验 6 用 0x0009 在空白 AIC 卡上写入成功。 正版发行卡经 0x0009 是否可写仍未复验。

实验 5：服务码探测

对 Konami AIC 卡用 Read 命令探测 0x0001-0x001F + 高位服务码：

  • 仅 0x000B 返回数据
  • 其余返回 01 A6（需认证）或 01 A8（不存在）
  • Request Service（0x02）命令：Lite-S 无响应

当时的结论：卡上没有第二个可用的隐藏服务。

同样需要更正

0x0009 在正版发行卡上读返回 01 A8，但在未发行的空白 AIC 卡上 读写完全正常（实验 6）。所以 0x0009 一直存在，只是发行后被限制了。

实验 6：空白 AIC 卡写入合法 Amusement IC 数据

对象：未发行的空白 AIC 卡（FeliCa Lite-S）

IDm: 01 2e 55 24 f1 48 57 3a
PMm: 00 f1 00 00 00 01 43 00      ← AIC 指纹
块 85: 88 b4                       ← AIC 系统码
块 82: IDm + 00 00                 ← DFC 全零，从未发行
块 01-04: 明文可读                  ← 没有 MAC 保护
块 00: 10 04 01 00 0d ... 00 36     ← NFC Forum Type 3 Tag 的 AIB
块 01-02: d1 01 0f 54 02 65 6e ...  ← NDEF 文本 "Hello World!"

这张卡被人当普通 Type 3 标签写过 NDEF，AIB 末 2 字节 00 36 正好等于前 14 字节之和，符合 Type 3 Tag 校验规则。

服务码探测（块 0x0D，每次写完立刻还原）：

服务码读写
0x000BOK01 A6 拒绝
0x0009OK成功，回读一致，还原成功
0x000A / 0x000D / 0x0008无响应无响应

写入流程（aic_pn532 工具，服务码 0x0009）：

  1. 全量备份 33 块（用户区 0x00-0x0E + 系统区 0x80-0x91）
  2. 可逆写探针：块 0x0D 写 A5/5A 图案 → 回读一致 → 还原全零 → 回读一致
  3. 生成 access code：501 + 十进制 IDm 补零到 17 位 = 50185099060121851706（形状与真 Sega 卡 50142788364534652126 一致）
  4. SPAD0 明文 = 00×6 + BCD(20 位)，用 hinata 的 spad0 算法加密 → fb5bef79392c868e66b5a28532b51f3d
  5. 写入块 0x00，回读一致
  6. 清掉块 0x01、0x02 的残留 NDEF（AIB 已被覆盖，NDEF 结构已失效）
  7. 用只读服务 0x000B 读回块 0x00 并解密 → dec[5] == 0 且 dec[6] & 0xF0 == 0x50，与 hinata 的 AIC 判定路径完全一致
  8. 写完再做一次块 0x0D 可逆探针 → 卡仍可反复擦写
  9. 全卡比对：只有 0x00、0x01、0x02 变化，写锁块 0x80 全程未动

结果：

access code     5018-5099-0601-2185-1706
SPAD0 密文      fb 5b ef 79 39 2c 86 8e 66 b5 a2 85 32 b5 1f 3d
e-amusement 卡号 AWRBU4A96GZRAB2F   （CardCipher 编码 IDm）

结论：

  • 空白 AIC 卡的用户区完全可写，写入通道是服务码 0x0009
  • access code 是服务端发号的，与 IDm 无数学关系（真卡尾段不等于十进制 IDm）， 所以这里只是借用 501 + 十进制 IDm 的形状，保证每张卡唯一且可复现
  • 空白卡做不出 MAC_A，需要 MAC_A 校验的服务端可能不认；私服不受影响
  • e-amusement 卡号只由 IDm 决定，写不写 SPAD0 都不变

环境备注

  • macOS（Apple Silicon），libnfc 1.8.0（Homebrew）
  • PN532 经 CH340 USB 转串口
